## 🌟 Overview & Core Philosophy

The **Smart Education Platform** is an intelligent education ecosystem designed to unify personalized academic learning, practical technical skill building, and professional career readiness into one continuous improvement cycle:

$$\text{Understand} \rightarrow \text{Personalize} \rightarrow \text{Learn} \rightarrow \text{Practice} \rightarrow \text{Test} \rightarrow \text{Analyze} \rightarrow \text{Detect Weakness} \rightarrow \text{Recommend} \rightarrow \text{Improve} \rightarrow \text{Re-Test} \rightarrow \text{Track Progress} \rightarrow \text{Build Skills} \rightarrow \text{Prepare for Career}$$

Rather than a disjointed set of disconnected utilities, every feature on the platform feeds directly into the student's longitudinal progress record, closing knowledge gaps and accelerating career readiness.

## Account & Permanent Progress

This build uses the Express backend as the source of truth for student accounts and learning progress.

1. Start the backend with `npm run server`.
2. Start the frontend with `npm run dev`.
3. Register once and save the generated User ID.
4. Log in later with the same User ID (or registered email/mobile) and password.
5. Learning progress, quiz analysis, weakness plan, re-test data, chat history, selected learning context, and programming-topic progress are stored per user in `server/data/users.json`.
6. Authentication sessions are stored in `server/data/sessions.json` so a browser can remain logged in after a page refresh or backend restart.

For a production/cloud deployment, replace the JSON files with a managed persistent database because serverless filesystems may not be durable.

## Local development: frontend + persistent account backend

The registration/login system requires the Node/Express backend on port 3001. The easiest way to run both pieces together is:

```bash
npm install
npm start
```

This starts:
- Vite frontend: http://localhost:5173
- Express backend: http://localhost:3001

Do not use only `npm run dev` if you want registration/login and server-backed progress persistence. If you prefer two terminals, run `npm run server` in one and `npm run dev` in the other.

User accounts and learning state are stored in `server/data/users.json` for this local prototype. Keep that file backed up; for production deployment, replace it with a persistent database.

The project now has a separate backend-authenticated admin portal dedicated to hackathon circulation.

For deployment, set `ADMIN_USER_ID` and `ADMIN_PASSWORD` in `.env` and change the demo password.

### Admin workflow
1. Open **Admin Login** from the platform.
2. Sign in with the admin credentials.
3. The backend issues an admin session token.
4. Only authenticated admin requests can add, edit, delete, publish, or unpublish hackathons.
5. Published hackathons are returned to the student-side `/api/hackathons` feed.
6. Hackathon data persists in `server/data/hackathons.json`, so changes survive server restarts.
